# 战斗结算规则

本文件描述玩法层面的具体结算顺序，不讨论伪代码语法。伪代码写法见 `EffectDsl.md`。

## 胜负与终止

- 任意一方英雄生命值降至 0 或以下时，立即判定胜负
- 胜负一旦产生：
  - 立即停止后续事件触发
  - 停止后续攻击、伤害、治疗、召唤、出牌与效果连锁
  - 不再结算亡语、额外攻击、光环刷新等后续效果
- `play_card` 在胜负产生后直接失败
- `advance_phase` 在胜负产生后不再推进阶段
- 已开始的伤害动作会在英雄死亡后立即返回，不继续后续命中

## 攻击形式

| 词缀 | 行为 |
|---|---|
| 先攻 `first_strike` | 每个攻击整轮只触发一次，先对敌方英雄造成数值伤害；双重打击、三连打、狂热追加、穿透都不会让它重复触发 |
| 双重打击 `double_strike` | 第一次完整攻击动作与死亡结算后仍存活，再执行一次完整攻击动作 |
| 三连打 `triple_strike` | 一次攻击动作依次攻击左列、自身列、右列；列不合法则跳过；每列是独立攻击 |
| 穿透 `strikethrough` | 单次攻击命中当前攻击列全部敌方实体，并命中敌方英雄；三连打时三列分别穿透各自列 |
| 溅射 `overshoot` | 主攻击后对攻击者所在列左右相邻列的**敌方实体**造成数值伤害；不伤害友方 |
| 狂热 `frenzy` | 单次攻击击杀被命中的敌方实体后，追加一次完整攻击动作；穿透击杀也会触发 |
| 反伤 `thorns` | 被普通单体攻击命中时，对攻击来源造成数值伤害；不是攻击，不改变攻击形式 |

## 三连打与穿透

- 三连打会分别以左列、自身列、右列为 `attack_column`
- 穿透使用该次攻击的 `attack_column`
- 因此三连打 + 穿透 = 左列穿透、自身列穿透、右列穿透
- 穿透不会因为三连打而重复命中同一列

## 事件顺序

单次攻击大致顺序：

1. 额外攻击事件（仅强制攻击/狂热追加）
2. 先攻英雄伤害（每个攻击整轮一次，不随双打/三连/狂热/穿透重复）
3. 主攻击/穿透/溅射伤害
4. 反伤（仅普通单体攻击）
5. `attack` 事件
6. `attacked` 事件
7. 狂热追加攻击
8. 死亡结算

### `attacked`

- 普通单体攻击：被选中的实体仍存活时触发
- 穿透：每个被穿透命中的敌方实体分别触发
- 三连打：每列目标分别触发
- 溅射：不会为溅射目标触发
- 反伤：不触发

### `damaged`

- 只有最终伤害 > 0 时触发
- 隐形、防御减伤、无敌、锦囊免疫等全部结算后判定
- 致命同样要求最终伤害 > 0

### `extra_attack`

- 强制攻击触发一次
- 狂热追加触发一次
- 双重打击第二次不触发
- 三连打本身不额外触发；额外攻击中只在第一击前触发一次

## 墓碑

- 墓碑内实体不会受到伤害，也不会成为普通实体锦囊目标
- 仍可被 `destroy`、`remove_entity` 和墓碑专用能力处理
- 揭示时先移除 `buried`，再结算 `frozen_tombstone`，再触发 `tombstone_reveal` 与 `enter`

## 生命值

- 生命值增益同时增加当前生命与上限，并触发 `healed`
- 生命值减益无视护盾、隐形、无敌，不触发 `damaged`
- 生命值减少后当前生命小于 1 时，即使有无敌也会死亡
- 治疗不能超过生命上限

## 回合阶段

- 起手调度：双方刷新起手牌，全部确认后开始第 1 回合
- 第 1 回合开始：发放能量、结算 `turn_start`、发放初始超能力
- Z 方实体牌阶段：Z 方只能打出实体牌
- P 方出牌阶段：P 方可正常出牌
- Z 方锦囊与环境阶段：只能打出锦囊牌、环境牌；拥有 `spell_phase_entity` 的实体牌例外
- 战斗阶段：逐列结算攻击、伤害与死亡
- 特殊回合：充能护盾满充能后可能进入，结算超能力
- 回合结束：逐列结算 `turn_end`、环境回合结束效果、死亡，隐形数值 -1，清除英雄护盾
- 下一回合：增加回合数、发放能量、结算 `turn_start`、抽牌，回到 Z 方实体牌阶段

当前没有独立的 P 方锦囊与环境阶段。

## 伤害与有效伤害

实体伤害统一经过 `damage_entity`，顺序为：

1. 战斗已结束、实体不存在或已死亡 → 无有效伤害
2. 实体在墓碑中 → 无有效伤害
3. 无敌、锦囊免疫、隐形免疫 → 无有效伤害
4. 非必中伤害先扣护盾：`max(amount - shield, 0)`
5. 最终伤害大于 0 才扣生命
6. 致命只在最终伤害大于 0 时把生命归零

`damage_entity` 返回本次**有效伤害**：

```text
damage > 0  = 有效伤害
damage == 0 = 未造成有效伤害
```

`damaged`、`health_changed`、致命、狂热击杀判定、仇恨等反应只应在有效伤害大于 0 时触发。`amount` 只用于战报展示，不参与事件和击杀判定。

## 无敌与消灭

- 无敌 Buff 免疫伤害
- 无敌实体仍可被消灭效果选中
- 消灭效果可以正常消灭无敌实体
- 致命攻击面对无敌实体不会造成伤害，也不会触发致命消灭
- 锦囊免疫仍然阻止锦囊选中和锦囊伤害

## 溅射

- 溅射只伤害攻击者所在列左右相邻列的敌方实体
- 溅射不会伤害英雄
- 溅射不会为被溅射目标触发 `attacked`
- 主攻击、穿透仍按各自规则正常命中英雄

## 充能护盾与特殊回合

- 英雄受到非必中伤害后获得充能
- 充能满时消耗耐久，触发免伤并发放超能力
- 特殊回合不会在攻击动画/伤害连锁中途强行切入
- 充能在战斗阶段触发时，会在战斗阶段整体结束后进入特殊回合
- 充能发生在出牌结算后、回合开始、回合结束时，会在对应安全节点进入特殊回合

## 环境赋予临时词缀

- 环境赋予的词缀使用 `temp_<keyword>` 临时词缀 Buff
- 临时词缀与实体自身词缀、卡牌赋予词缀叠加
- 环境覆盖时只移除旧环境赋予的临时层数
- 实体离开环境列时移除该环境赋予的临时词缀
- 实体进入环境列时按环境条件重新赋予
- 环境只检测与其同一列的实体，不检测其他列
- 默认环境赋予是临时的；显式使用 `environment_grant_keyword_persistent` 才是持久赋予

## 费用

- 手牌有效费用始终不低于 0
- 场上实体的费用固定为卡牌数据库原始费用
- 手牌减费、特殊回合减费不会改变场上实体费用

## 目标选择

- 单目标法术使用解析后的 `chosen` 目标节点判定
- 多目标能力默认是“最多选择”，不是必须选满
- 没有剩余合法目标时自动退出选择
- 目标选择期间不能进行其他出牌操作
- 无目标、随机目标、全体目标法术不需要选择目标

## 入场当回合能力

实体入场时记录 `entered_turn`。事件条件可使用：

```text
when turn_end(entered_this_turn):
    buff_stats(self, -1, 0)
```

该能力只会在实体入场当回合的回合结束时触发，后续回合不再触发。

## 反伤与有效伤害

- 反伤只在本次攻击的实际有效伤害 `> 0` 时触发
- 目标无敌、隐形免疫、锦囊免疫或护盾完全挡下时，不触发反伤
- 反伤伤害会携带反伤来源实体当前拥有的词缀（先攻、致命、寒霜、必中等），并额外标记为反伤
- 反伤不是攻击，不会触发攻击形式词缀（双重打击、狂热、穿透、三连打、先攻）

## 特殊能力伤害与攻击形式

实体特殊能力通过 `deal_damage` 等原语造成伤害时：

- 会携带该实体当前词缀，因此致命、寒霜、必中等伤害类型正常生效
- 不会进入攻击流程，因此不会触发先攻
- 不受双重打击、狂热、穿透、三连打、溅射等“改变攻击形式”的词缀影响
- 不会触发 `attack` / `attacked`
- 不会触发被伤害目标的普通反伤（反伤只响应攻击）
- 会正常触发 `damaged` / `health_changed`

只有明确调用额外攻击或进入实体攻击流程的能力，才会使用双重打击、狂热、穿透、三连打、先攻等攻击形式规则。

## 职业类别

- 全局配置定义职业类别及其所含职业
- 每个职业只能属于一个类别
- 未配置职业自动进入“未分类”
- 卡牌筛选支持 `category` 字段
- 变形、混乱进化、混乱手牌都使用职业类别作为筛选条件

## 变形

- 变形效果把原实体原地移除，再按卡牌筛选条件随机召唤新实体
- 新实体正常入场并触发入场效果
- 变形会触发 `transformed` 事件，事件实体为新实体
- 手牌变形会替换手牌实例的卡牌 ID，并触发 `hand_transformed`

## 混乱进化

- 拥有 `chaos_evolution` 的实体在回合结束时变形
- 筛选条件为：费用比自身高 1、职业类别相同、类型为实体
- 新实体获得 `chaos_evolution`
- 由全局变形流程赋予词缀，不依赖原实体继续存在

## 混乱手牌

- 拥有 `chaos_hand` 的手牌在回合开始时变形
- 筛选条件为：费用比自身高 1、职业类别相同、类型相同
- 新卡获得 `chaos_hand`
- 该词缀只在手牌中发挥作用

## 生命力量

- `life_force` Buff 让实体攻击伤害改用当前生命值
- 攻击力为 0 但当前生命值大于 0 时，仍可攻击
- 主攻击、穿透、溅射都用当前生命值
- 双重打击、狂热、三连打每段攻击都重新读取当前生命值
- 先攻不改成生命值，仍使用先攻词缀数值
- 目标的护盾、无敌、隐形、锦囊免疫、必中等抗性照常结算

## 创造牌与施加效果

- `draw_cards` 只是从牌库移动已有牌，不创建新牌
- `add_random_cards` 按筛选条件从卡牌数据库抽取卡牌，创建新实例并随机插入手牌或牌库
- 创建时支持费用修正 `cost_delta`
- `put_random_card_on_deck_top` 创建一张牌放到牌库顶
- 当前 DSL 的创建原语只返回数量，不返回具体新实例句柄；创建后无法在同一条原语里直接指定“这张新牌”加词缀
- 可以在创建后通过手牌索引再施加词缀；实体创建可通过 `summon` 正常入场并受入场效果影响
- 新创建的手牌会受手牌费用光环、手牌变形和后续手牌效果影响

## 环境临时数值

- 环境可以临时赋予同列实体攻击力、生命值、防御值
- 与临时词缀一样，离开列、环境覆盖或实体死亡时移除
- 进入列时重新按环境条件应用
- 环境数值不是永久属性，不改变卡牌数据库原始数值

## 底座与进化

- 进化实体放置在底座上时先结算底座 `mounted`
- 底座能力结算后再判断是否满足进化条件
- 满足条件才触发 `evolved`
- 若底座能力导致新实体离场/死亡，不再触发进化

## 搜寻抽牌

- `draw_matching_cards` 从当前牌库随机选择符合筛选条件的牌
- 只移动已有牌，不创造新牌
- 每张抽到的牌都会触发 `drawn`
- 费用修正可应用到本次抽到的每张牌
- 牌库为空时抽牌失败并增加疲劳

## 疲劳

- 牌库为空时执行抽牌，会为该阵营英雄添加 1 层 `fatigue`
- 回合开始时，英雄受到等同于疲劳层数的伤害
- 该伤害来源为“疲劳”
- 该伤害不是攻击、不是锦囊，不使用致命/寒霜/必中词缀
- 会正常触发英雄护盾、充能护盾和特殊回合
- 疲劳不会自动减少

## 标志物

- 标志物只存储在玩家英雄上
- 当前不支持实体标志物
- 标志物名称不注册，允许任意字符串
- 数量可以为负数
- 当前原语可添加、移除、查询施放者英雄的标志物
- 标志物不会自动消耗，需要能力显式移除
