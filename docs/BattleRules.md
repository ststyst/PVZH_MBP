# 战斗结算规则

本文件描述当前已经实现的玩法层面规则，不讨论伪代码语法。伪代码写法见 `EffectDsl.md`。

## 一、基础战场与数值

- 战场为 5 列 × 双方各 2 个位置
- 每个位置分为普通位和组队位
- 默认牌库 40 张，手牌上限 10 张
- 默认英雄生命上限 20
- 默认初始抽 4 张
- 默认每回合抽 1 张；第 1 回合只发起手牌
- 默认阶段时限 40 秒；与电脑对战时取消该时限
- 默认费用上限 99
- 每回合费用重置为：初始费用 1 + 当前回合数 - 1
- 费用不跨回合累积

## 二、卡牌类型与费用

### 实体牌 `entity`

- 打出后召唤到场上
- 拥有攻击力、生命值、防御值
- 场上实体费用固定为卡牌数据库的原始费用
- 手牌减费不会改变场上实体费用

### 锦囊牌 `spell`

- 打出后执行能力并进入弃牌区
- 可以没有目标、指定单体目标或选择多个目标
- 可以拥有 `superpower` 词缀作为超能力牌

### 环境牌 `environment`

- 放置到某一列
- 环境效果默认只影响同一列
- 可以被其他环境覆盖，受保护环境除外

### 手牌有效费用

- 手牌有效费用始终不低于 0
- 手牌有效费用 = 原始费用 + 实例费用修正 + 光环修正 - 特殊回合减费
- 实例费用修正可以来自抽牌、创建牌、能力效果等

## 三、回合阶段

### 1. 起手调度

- 双方各抽初始手牌
- 每张牌可以刷新一次
- 双方确认后进入第一回合

### 2. 回合开始

- 发放能量
- 逐列结算 `turn_start`
- 结算疲劳伤害
- 结算混乱手牌变形
- 从第二回合开始，双方各抽 1 张
- 检查充能护盾特殊回合

### 3. Z 方实体牌阶段

- Z 方只能打出实体牌
- 不能打出锦囊或环境牌
- 结束后进入 P 方出牌阶段

### 4. P 方出牌阶段

- P 方当前可以正常出牌
- 结束后进入 Z 方锦囊与环境阶段

### 5. Z 方锦囊与环境阶段

- 只能打出锦囊牌、环境牌
- 拥有 `spell_phase_entity` 的实体牌例外
- 阶段开始时揭示墓碑
- 结束后进入战斗阶段

### 6. 战斗阶段

- 按列依次结算
- 结算攻击、伤害、死亡、反伤、狂热等
- 战斗阶段结束后检查特殊回合

### 7. 特殊回合

- 由充能护盾满充能触发
- 选择立刻打出超能力，或移入手牌
- 不会在攻击动作中途强行切入
- 通常在出牌结算后、战斗结束后、回合结束后进入

### 8. 回合结束

- 逐列结算 `turn_end`
- 结算混乱进化
- 结算环境回合结束效果
- 结算死亡
- 隐形数值 -1
- 清除英雄护盾
- 检查特殊回合，然后进入下一回合

当前没有独立的 P 方锦囊与环境阶段。

## 四、行动与目标选择

- 实体牌需要选择合法放置位置
- 环境牌需要选择列
- 需要目标的法术使用解析后的 `chosen` 目标
- `choose(count, selector)` 为最多选择，不是必须选满
- 没有剩余合法目标时自动退出目标选择
- 目标选择期间不能进行其他出牌操作
- 无目标、随机目标、全体目标法术不需要手动选择目标
- 当前可以以英雄为目标；敌方英雄与我方英雄都可以成为合法目标

## 五、伤害与有效伤害

实体伤害统一经过 `damage_entity`：

1. 战斗已结束、实体不存在或已死亡 → 无有效伤害
2. 实体在墓碑中 → 无有效伤害
3. 无敌、锦囊免疫、隐形免疫 → 无有效伤害
4. 非必中伤害先扣护盾：`max(amount - shield, 0)`
5. 最终伤害大于 0 才扣生命
6. 致命只在最终伤害大于 0 时把生命归零

返回值：

```text
damage > 0  = 有效伤害
damage == 0 = 未造成有效伤害
```

只有有效伤害大于 0 才触发：

- `damaged`
- `health_changed`
- 致命消灭
- 狂热击杀判定
- 仇恨反击
- 寒霜附加冻结

`amount` 只用于战报展示。

## 六、生命、护盾与英雄充能

- 实体防御是固定减伤，每段伤害都按防御值减免，不会消耗
- 英雄护盾先吸收伤害，并减少护盾值
- 英雄护盾在回合结束时清零
- 治疗不能超过生命上限
- 生命上限变化时当前生命不能超过新上限
- 生命值减益不是伤害，不经过伤害抗性
- 英雄没有攻击力，英雄不会主动攻击

### 英雄受伤顺序

英雄受到伤害时按以下顺序结算（`damage_hero`）：

1. 对局已结束 / 伤害 ≤ 0 → 直接忽略
2. 英雄伤害免疫（`hero_damage_immune`）→ 本次伤害作废
3. **守护英雄**：若我方有在场且拥有 `hero_guard` 的存活实体，则挑选当前生命最高的那个，
   由它承受本次伤害（按该实体自身的防御、无敌、隐形、墓碑等规则结算一次，
   **英雄护盾、充能、生命都不受影响**）；守护实体倒下后，多余伤害不会溢出到英雄
4. 英雄护盾吸收（减少护盾值），若已被完全吸收则结束
5. **英雄壁垒**：若我方有在场且拥有 `hero_ward` 的存活实体，本次伤害最多把英雄生命打到 1
   （已经为 1 时伤害归零）
6. 真实受击：必中以外的伤害获得充能；致命且还有致命保护时改为获得 3 充能；
   充能满足上限则本次免伤并进入特殊回合
7. 扣除生命、记录伤害来源、检查胜负

### 充能护盾

- 默认上限 8，耐久 3，致命保护 1 次
- 非必中真实伤害获得充能：
  - 1-3 点伤害 → 1 充能
  - 4-6 点伤害 → 2 充能
  - 7 点以上 → 3 充能
- 满充能时消耗 1 点耐久，本次伤害免伤，并进入特殊回合
- 致命伤害时可以消耗一次致命保护，改为获得 3 充能
- 必中伤害不增加充能

## 七、词缀

### 当前实际接入战斗结算的词缀

| 词缀 | 效果 |
|---|---|
| 先攻 `first_strike` | 每个攻击整轮只触发一次，先对敌方英雄造成数值伤害 |
| 致命 `deadly` | 有效伤害大于 0 时直接把目标生命归零 |
| 穿透 `strikethrough` | 命中当前攻击列全部敌方实体，并命中敌方英雄 |
| 溅射 `overshoot` | 主攻击后伤害左右相邻列的敌方实体，不伤害英雄 |
| 双重打击 `double_strike` | 第一次完整攻击后仍存活，再攻击一次 |
| 三连打 `triple_strike` | 依次攻击左列、自身列、右列 |
| 狂热 `frenzy` | 击杀被命中实体后追加一次攻击 |
| 必中 `bullseye` | 伤害绕过护盾、隐形，不增加充能 |
| 寒霜 `frost` | 有效伤害后附加冻结 |
| 反伤 `thorns` | 被普通攻击命中且受到有效伤害时反击 |
| 隐形 `invisible` | 没有必中时免疫伤害；回合结束数值 -1 |
| 无敌 `invincible` | 免疫伤害；仍可被消灭效果正常消灭 |
| 锦囊免疫 `spell_immune` | 不会被锦囊选中，锦囊伤害无效 |
| 免疫锦囊 `untrickable` | 与锦囊免疫相同的不可选中效果 |
| 免疫负面 `debuff_immune` | 不会获得 Debuff |
| 墓碑 `tombstone` | 入场时埋入墓碑，按阶段揭示 |
| 组队 `team_up` | 允许同列第二个实体，并可挤开现有实体 |
| 两栖 `amphibious` | 满足水池等环境的位置要求 |
| 捕猎 `hunt` | 敌方实体入场时尝试移动到其列 |
| 克制英雄 `hero_counter` | 同列没有敌方实体时获得临时攻击力 |
| 守护英雄 `hero_guard` | 在场时，我方英雄受到的伤害改由该实体承受（多个时选当前生命最高者） |
| 英雄壁垒 `hero_ward` | 在场时，我方英雄生命值不会低于 1 |

### 已注册但当前未接入战斗结算的词缀

- 冲锋 `charge`
- 嘲讽 `taunt`
- 护甲 `armored`

这些词缀目前只存在于词缀表和卡面展示，不会改变战斗行为。

## 八、攻击与事件顺序

### 战斗阶段的整轮流程

轮到战斗阶段时（`_resolve_combat`）：

1. 从第 1 列到第 5 列**依次**结算；一旦分出胜负立即中断后续列
2. 每列先收集攻击者：Z 方该列全部存活实体，再 P 方该列全部存活实体（各按入场顺序）
3. **第一轮攻击**：逐个执行一次攻击动作（跳过被冰冻、攻击力 < 1 的实体）。
   这一轮**先全部打完，再统一结算死亡**——所以同列互击时双方都会出手
4. `_flush_column_deaths`：该列生命值 < 1 的实体一次性死亡，触发 `die` / `ally_die`
   （同阵营有“双亡语”实体时 `die` 触发两次），随后刷新光环与克制英雄加成、检查胜负
5. **双重打击 `double_strike`**：第一轮与死亡结算后仍存活、未冰冻且攻击力 ≥ 1 的实体再攻击一次
6. 再次结算该列死亡
7. 清理该列的“战斗后解除”Buff（`frozen` 冰冻、`invincible` 无敌）
8. 进入下一列

### 单次攻击动作内部的事件顺序

一次攻击动作（`_execute_attack_action` → `_execute_entity_attack`）：

1. `extra_attack`：仅“额外 / 强制攻击”时触发（战斗阶段第一轮不带；狂热追加、`force_attack` 带）
2. **先攻 `first_strike`**：整轮每个实体只触发一次，数值直接打敌方英雄，走英雄受伤流程，
   **不触发** `attack` / `attacked`
3. **主伤害**：
   - 普通攻击：同列第一个存活敌方实体；该列没有敌方实体则打敌方英雄
   - 穿透 `strikethrough`：攻击列内每个敌方实体 + 敌方英雄
   - 每个受伤实体在结算时触发 `damaged`、`health_changed`（仅有效伤害 > 0）
4. **反伤 `thorns`**：仅普通攻击命中实体且造成有效伤害时反击（穿透不触发）
5. **溅射 `overshoot`**：主攻击后对左右相邻列所有敌方实体造成伤害（**不触发** `attacked`，不伤英雄）
6. `attack`：攻击者自身触发一次（打英雄也会触发）
7. `attacked`：普通攻击的主目标仍存活时触发；穿透为每个被命中且存活的实体各触发一次；
   打英雄、溅射目标、反伤都不触发
8. `after_attack`：攻击者仍存活时触发一次。它在**死亡判定之前**结算——被击杀的实体此时仍在场
   （生命 ≤ 0 但尚未移除），所以 `after_attack` 里的 `all_enemies` / `entities_matching(...)`
   仍能看到它
9. **狂热 `frenzy`**：击杀被命中实体后先结算死亡，再追加一次完整攻击（递归上限 8），
   追加攻击带 `extra_attack` 并拥有自己的 `after_attack`
10. `damage_dealt`：每次事件派发结束时按来源批量结算，目标汇总到 `damage_targets`
    （实体与英雄目标都会包含）

### 其他阶段里的攻击

非战斗阶段只有一种方式能产生攻击：卡牌效果的 `force_attack(target)`（以及由它引发的狂热追加）。
它与战斗阶段有一处**结构性差异**：

- 立刻结算这**一个**攻击动作，然后**只结算该列**的死亡，并清理该列的战斗后 Buff
  （三连打跨列击杀时，其他列的死亡要等下一次结算）
- 不会触发“双重打击”的第二段（那是战斗阶段按列批处理的逻辑）
- 先攻的“整轮一次”标记只在战斗阶段开始时清空，所以本回合战斗阶段已经先攻过的实体，
  在其他阶段被强制攻击时不再触发先攻
- 三连打、穿透、溅射、反伤、狂热、`attack` / `attacked` / `after_attack` / `damage_dealt` 照常生效
- 目标选择与战斗阶段共用同一套逻辑（同列第一个存活敌方实体，否则英雄）
- 嘲讽 `taunt`、冲锋 `charge` 尚未接入结算，所以不存在“嘲讽优先”或“入场立刻攻击”

### 生命力量

- `life_force` Buff 让攻击伤害改用当前生命值
- 攻击力为 0 但生命值大于 0 时仍可攻击
- 主攻击和穿透使用当前生命值
- 溅射仍使用溅射词缀数值
- 先攻仍使用先攻词缀数值
- 双重打击、三连打、狂热每段攻击重新读取当前生命值
- 目标抗性照常结算

### 攻击事件

- `attacked`：普通攻击目标仍存活时触发
- 穿透：每个被命中且存活的实体分别触发
- 三连打：每列目标分别触发
- 溅射：不为溅射目标触发
- 反伤：不触发

## 九、特殊能力机制

### 创造牌

- `add_random_cards_to_hand` / `add_random_cards_to_deck`：从卡牌数据库创建新牌
- `put_card_on_deck_top`：创建一张牌放到牌库顶
- 创建时默认从卡牌数据库读取，不消耗现有牌库
- 可以内联施加：费用修正、一个词缀及其数值、攻击修正、生命修正、防御修正
- 多张创建时对每一张都施加相同效果
- 创建牌不会修改数据库原始卡牌

### 抽牌

- `draw_cards`：从牌库顶抽已有牌，不创建新牌
- `draw_matching_cards`：从当前牌库随机搜寻符合筛选条件的牌到手牌
- 两者都会触发 `drawn` 事件
- 抽牌失败（牌库为空）添加 1 层疲劳
- 手牌满时停止抽牌

### 变形

- `transform`：移除原实体，在原位置按筛选条件随机召唤新实体
- 新实体正常入场
- 触发 `transformed` 事件
- `transform_hand`：替换手牌实例的卡牌 ID
- 触发 `hand_transformed` 事件

### 环境临时效果

- 环境可临时赋予同列实体词缀
- 环境可临时赋予同列实体攻击力、生命值、防御值
- 实体离开环境列时移除
- 实体进入环境列时重新应用
- 环境被覆盖时移除旧环境赋予的临时效果
- 默认环境词缀是临时的；`environment_grant_keyword_persistent` 为持久赋予

### 底座与进化

1. 进化实体放置到底座上
2. 新实体正常入场
3. 先结算底座 `mounted` 能力
4. 再判断是否满足进化条件
5. 满足时触发 `evolved`
6. 底座能力导致新实体离场或死亡时不再触发进化

### 标志物

- 标志物只存储在玩家英雄上
- 名称不注册，允许任意字符串
- 数量可以为负数
- `add_marker` / `remove_marker` 默认作用于施放者英雄
- `marker_count` 查询施放者英雄
- 标志物不会自动消耗

## 十、特殊状态与词缀

### 混乱进化 `chaos_evolution`

- 仅实体可拥有
- 回合结束时变形为费用 +1、职业类别相同的随机实体
- 新实体获得 `chaos_evolution`
- 由全局变形流程赋予词缀

### 混乱手牌 `chaos_hand`

- 任何类型牌都可以拥有，仅在手牌中生效
- 回合开始时变形为费用 +1、职业类别相同、类型相同的随机手牌
- 新卡获得 `chaos_hand`

### 生命力量 `life_force`

见“攻击与事件顺序”。

### 疲劳 `fatigue`

- 牌库为空仍要抽牌时获得 1 层
- 回合开始时英雄受到等同层数的伤害
- 来源为“疲劳”
- 类型为普通非攻击、非锦囊伤害
- 会经过英雄护盾、充能护盾和免伤
- 不会自动减少

## 十一、职业与职业类别

- 全局配置定义职业类别及其成员职业
- 每个职业只能属于一个类别
- 未配置职业自动归入“未分类”
- 卡牌筛选支持 `category`
- 变形、混乱进化、混乱手牌使用职业类别筛选

## 十二、胜负与终止

- 任意一方英雄生命值降至 0 或以下时立即判定胜负
- 胜负产生后：
  - 停止后续事件
  - 停止攻击、伤害、治疗、召唤、出牌
  - 不再结算亡语、额外攻击、光环
- 已开始的伤害会在英雄死亡后立即返回

## 同列前后位置伤害

- `front` 对应普通位，`back` 对应组队位
- 目标列只有一个敌方实体时，`front`/`back` 都会命中它
- 支持相对列偏移：`0` 当前列、`-1` 左侧列、`1` 右侧列
- 实体能力以自身所在列为参考列
- 选列锦囊以玩家选择的列为参考列
- 环境牌以自身所在列为参考列
- 只伤害敌方实体，不命中英雄
- 不属于攻击，不触发先攻、双击、狂热、穿透、三连等攻击形式
- 伤害会携带施放者词缀

## 攻击完成事件

`after_attack` 在实体完成一次攻击动作后触发。

- 事件实体是攻击者
- 每次实际执行的攻击动作触发一次
- 双重打击触发两次
- 三连打按列触发三次
- 狂热追加攻击会额外触发
- 穿透一次攻击只触发一次
- 强制攻击和额外攻击会触发
- 攻击者被反伤杀死时不再触发
- 先攻直接结束对局时不触发
- 特殊能力伤害不是攻击，不触发

## 造成有效伤害事件

- `damage_dealt` 在伤害来源实体造成有效伤害后触发
- 只有有效伤害大于 0 才触发
- 攻击和特殊能力伤害都会触发
- 反伤、充能免伤、护盾完全挡下不触发
- 多目标伤害会汇总到 `damage_targets` 数组，触发一次事件
- 数组可包含实体和英雄句柄；英雄目标的 `class` 事实为 `hero`，可据此分流
- `damaged` / `hero_damaged` 都能读到伤害来源（`damage_source`）与有效伤害数值（`damage_amount`）；
  锦囊 / 环境 / 无来源伤害的来源为空
- 逐元素回调请用 `for_each`（见文末「逐目标循环结算」）

## 逐目标循环结算

卡牌能力可以对一组目标**逐个展开**结算，并对每个目标单独判定：

```text
for_each(all_enemies) as e:
    if health <= 3:
        destroy(e)
    elif cost >= 5:
        deal_damage(e, 2)
    else:
        deal_damage(e, 1)
```

玩法语义：

- **逐个独立结算**：每个目标各自走一遍完整流程。上一轮造成的变化会立刻影响下一轮看到的数据（例如前一个目标被打死、离场后，后续目标按最新盘面判定）。
- **读到的是自己的当前值**：块内 `attack` / `health` / `max_health` / `shield`（即防御）/ `cost` / `side` / `class` / `tribes` / `keywords` / `buffs` / `column` / `turn` / `entered_this_turn` 都是该目标此刻的数值，不是能力拥有者的数值。
- **按目标分流**：`if` / `elif` / `else` 可以按目标自己的攻击、生命、防御、费用、流派、词缀、Buff、位置走不同分支、调用不同能力。
- **可嵌套**：一层循环里可以再套一层（例如“对每个受伤目标，遍历我方所有治疗者”）。内层读到的是内层目标的数据，读外层目标用 `attack(外层变量)` 这类双参数查询。
- **数组来源**：选择器（全部敌方 / 全部友方 / 受伤友方 / 墓碑等）、事件回调数组（如 `damage_targets`）、列内查询结果、随机目标结果都可以作为循环对象。
- **与“目标数组参数”的区别**：`deal_damage(all_enemies, 2)` 是同一次结算展开、所有目标参数一致；`for_each` 是每个目标重新结算，因此参数可以不同。
- **空目标**：没有目标时不执行任何内容，也不会报错。

完整语法、可读字段表与示例见 `docs/EffectDsl.md` 第十节。

## 按数值挑选目标

卡牌能力可以在一个范围内挑出**当前数值**最高 / 最低的实体，并对它（们）施加效果：

```text
deal_damage(highest(all_enemies, 'attack'), 3)
destroy(lowest(all_allies, 'health'))
apply_buff(lowest(enemy_entities, 'defense'), 'frozen')
```

玩法语义：

- **范围**：任意目标集合——全部敌方 / 全部友方 / 敌我全体 / 某列实体 / 受伤友方 / 随机若干 / 事件回调数组（如 `damage_targets`）等。
- **可先收窄范围**：可以附加一个逐目标条件，只有满足条件的候选才参与比较（例如“只看当前生命 ≥ 5 的敌方”“只看带嘲讽的友方”）。
- **数值**：攻击力、当前生命值、生命上限、防御值、费用；都是**结算后的当前值**（已包含 Buff、光环、环境修正），不是数据库里的原始数值。
- **并列**：所有并列最高 / 最低的实体都会成为目标（两张实体攻击力同为 7，就都吃这次效果）。
- **只接受单个目标的原语**：`apply_buff` / `remove_buff` / `force_attack` / `move_entity` / `remove_entity` 这类原语在并列时会结算失败（记录运行错误、不生效）。
- **空范围**：范围内没有实体时什么都不发生，也不报错。
- **免疫权限**：挑选本身不看锦囊免疫 / 隐形，但效果真正生效时仍按原语自身的规则过滤（锦囊伤害依旧打不到锦囊免疫的实体）。

完整语法与数值名列表见 `docs/EffectDsl.md`「按数值挑选目标」。

## 按卡牌筛选语法筛选在场实体

在场实体也能直接用**卡牌数据库的筛选语法**筛选（职业、职业类别、流派、词缀、费用、稀有度、英文名、类型、是否可编入牌组）：

```text
destroy(entities_matching("class == 'soldier' and cost <= 3"))
heal(entities_matching(all_allies, "tribe == 'pea'"), 2)
deal_damage(entities_matching(enemy_entities, "keyword == 'taunt'"), 1)
```

玩法语义：

- **范围**：省略范围时筛选**全部在场实体**（双方、存活）；给出范围时只在该范围内筛（全部敌方 / 全部友方 / 某列 / 随机若干 / 事件回调数组等）。
- **按当前状态判定**：战斗中被 Buff 或环境临时赋予的词缀同样参与匹配；费用取当前费用，不是数据库原值。
- **流派 / 词缀是“包含”语义**：实体同时具备多个流派或词缀时，命中任意一个即可。
- **默认要求可编入牌组**：没有显式写 `deck_includable` 条件时，不可编入牌组的实体（例如各种令牌）会被排除；要专门包含令牌，请显式写 `deck_includable == false`。
- **筛选写错**：该能力不生效，并在运行错误里记录筛选语法问题。
- **空结果**：没有实体符合条件时什么都不发生。

字段、运算符与组合写法见 `docs/EffectDsl.md`「用卡牌筛选语法筛选在场实体」。

## 英雄受伤事件

- 英雄受到**有效伤害**时触发 `hero_damaged`，事件目标是受伤的英雄
- 护盾完全吸收、充能免伤、英雄壁垒挡下时都不触发
- 监听方必须写过滤条件（`side == 'ally'` / `'enemy'`），因为英雄没有自己的技能
- 环境牌不监听该事件（英雄没有所在列，否则会按 5 列重复触发）
- 与 `damaged` 互补：`damaged` 只对实体触发，`hero_damaged` 只对英雄触发
- 两者都能读到伤害来源 `damage_source` 与有效伤害 `damage_amount`

## 伤害来源事实

`damaged` / `hero_damaged` 事件里可以拿到伤害来源：

- `damage_source`：来源句柄；锦囊 / 环境 / 无来源效果伤害为空
- `is_entity(damage_source)`：来源是否为实体（英雄与空来源都返回 false）
- `damage_amount`：本次有效伤害数值

示例（带刺玫瑰式效果）：

```text
when damaged(side == 'ally'):
    if is_entity(damage_source):
        destroy(damage_source)
```
