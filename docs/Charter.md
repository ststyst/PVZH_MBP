## 1. 一句话概述

一款类《炉石传说》的**卡牌回合制对战游戏**：玩家收集卡牌、自由构筑牌组，与电脑或真人对手对战；跨 Windows 与 Android。

## 2. 类型与平台

- 类型：卡牌回合制对战（以 1v1 为核心，可扩展娱乐模式）。
- 引擎与语言：Godot 4.7.2 + GDScript。
- 平台：Windows、Android（同一工程，鼠标键盘与触屏共用一套 UI）。
- 显示基准：竖屏 720×1280（9:16），`canvas_items` 拉伸、`keep` 适配（窗口比例不符时留黑边，画面完整）；手机锁竖屏，桌面窗口按屏幕可用区域自适应。

## 3. 网络模型（个人开发者规模，参照 Minecraft）

| 编号 | 需求 |
|---|---|
| a | 单机必须可玩，完全不依赖网络 |
| b | 内置**局域网搜索**：发现同网段玩家并发起对战 |
| c | 提供**可选的专业专用服务端**：普通玩家无需安装；面向有更高需求的用户，可通过内网穿透或公网 IP 让它像网游服务器一样运行 |
| d | 玩家可自由选择：单机游玩、搜索局域网玩家、或登录上述专用服务端 |

## 4. 玩家身份与存档（关键差异）

游戏在「单机身份」与「服务器身份」下差异明显，存档必须区分：

- **单机身份**
  - 可自由游玩全部人机内容；
  - 可在当前局域网搜索其他玩家对战；
  - 存档保存在**本地**；
  - 未来要适配模组（现在只预留，不做具体模组功能）。
- **服务器身份**
  - 服务端可禁用原主线内容（由服主配置）；
  - 局域网搜索功能**关闭**；
  - 玩家对战匹配由**服务器接管**；
  - 存档由**服务器代理**；
  - 本地只保存：最近登录服务器地址等信息 + 玩家输入的账号密码（便于下次登录）。

本地可保留**复数存档**并支持切换；两种身份的存档不得互相污染。

## 5. 功能模块

| 模块 | 内容 |
|---|---|
| a. 登录 | 本地存档（多存档切换）或服务器登录（IP + 账号密码） |
| b. 主界面 | 各模块的中转站，以 UI 为主 |
| c. 战斗 | 组好牌组后与电脑或网络对手对战；含娱乐模式 |
| d. 收藏与牌组 | 卡牌大背包；按限制构筑多个牌组；**一张牌可同时编入多个牌组**；用道具购买卡包随机获得卡牌；用**特殊货币合成**卡牌、**分解**卡牌获得该货币 |
| e. 社交（仅服务器身份） | 加好友、文字聊天、发起对战 |
| f. 活动（仅服务器身份） | 服主自行配置：推关玩法、对战规则改版、签到奖励等 |

## 6. 编码规范（用户指定，必须遵守）

1. GDScript。
2. 场景文件、类名、全局变量：驼峰命名法（本项目按**大驼峰 PascalCase** 执行，与既有 `LoginScreen.tscn` 一致）。
3. 文件夹名、脚本名、函数名、非全局变量名：蛇形 `snake_case`。
4. 枚举：全部大写（枚举名与成员均大写）。
5. 定义变量时尽量写具体类型，少用不确定类型（避免裸 `Variant`）。

## 7. 美术素材

- 需要图片时**优先留空**（不引用任何图片）。
- 实在不能留空时，生成**完全透明**的占位素材。
- 不引入来源不明或版权不清的素材。

## 8. 首版非目标（暂不做）

账号云端体系、反作弊、跨服、观战、成就、内购支付、正式美术与音效、完整剧情战役。

## 9. 阶段性验收标准

1. Windows 与 Android 均可运行「登录 → 主界面 → 牌组 → 人机对战」闭环。
2. 两台设备在同一局域网内可互相发现并发起一局对战。
3. 专用服务端可独立运行；客户端可登录并按服务器配置游玩，存档由服务器保存。
4. 全部代码符合第 6 节规范；工程无脚本解析错误，可 headless 冒烟通过。
